# Code quality research: Komi Store and kotlinconf-app

Status: decisions made on 2026-10-19 (section 5). The rules they produce live in [`docs/code-style.md`](../code-style.md); this file keeps the evidence.

- Komi Store: `origin/main` at [`cfa6bd30`](https://github.com/komi-store/komi-store/tree/cfa6bd30e6b35cbbc369d78a4599182a9a66beac) (2026-10-18). Links into our code are permalinks to that commit, so they stay correct as the code moves.
- kotlinconf-app: [`2189155`](https://github.com/JetBrains/kotlinconf-app/tree/218915583d0941e5cf67b839280fef79400e7b20), links are pinned to it.

## How this was made

- 8 read-only research agents walked both codebases on the same 15 dimensions: 2 on kotlinconf-app (non-UI and UI), 6 covering all 13 Komi features, `core/*`, `composeApp`, `build-logic` and CI.
- Lint numbers come from actually running ktlint 1.8.0 with the Compose rules on all 37 modules in a scratch worktree (section 2).
- Every link was checked twice. A script confirmed that each file and line exists, then three verifier agents re-read all 277 citations against the code: 259 were right as written and 18 were corrected. The bugs in section 3 marked "verified" were also re-read by hand.
- Agents can still misread code. Treat a single citation as a pointer, not proof, until someone looks.

## TL;DR

1. **kotlinconf-app is a source of techniques, not a quality bar.** It has no lint, two client test files, a 587-line god service, Boolean flags for one-off events and no stateless screen layer. Copying it wholesale would lower our bar in several places (section 1).
2. **Our biggest problem is internal drift, not missing kotlinconf patterns.** Five ViewModel shapes, three ways to navigate, three repository error contracts, no rule for user-facing text, and `CancellationException` swallowed in dozens of places (section 7).
3. **Lint covers 1 of 37 modules.** With ktlint on everywhere, hand-written code has 6,184 violations. A one-time `ktlintFormat` fixes all but 201 of them and touches 551 files (section 2).
4. **The CLAUDE.md files describe code that no longer exists**: routes, repositories, components, injected dependencies, cache TTLs. Agents read them on every task. Fixing the docs is the cheapest high-leverage step (section 8).
5. **The research found real bugs**, listed apart from style in section 3: per-host access tokens are never sent (regression since #666), the Desktop database is wiped on the next schema bump, a rate-limit exception can escape into `viewModelScope`, and more.

Run details: ktlint 1.8.0 (already pinned in [KtlintConventionPlugin.kt:11](https://github.com/komi-store/komi-store/blob/cfa6bd30e6b35cbbc369d78a4599182a9a66beac/build-logic/convention/src/main/kotlin/KtlintConventionPlugin.kt#L11)), the project `.editorconfig`, plus `io.nlopez.compose.rules:ktlint:0.6.0`.

Three things came out of making the run work. The first two concern ktlint-gradle, which [#1056](https://github.com/komi-store/komi-store/pull/1056) replaces with Spotless; the third still decides which Compose rules version works:

1. **The generated-code filter does not work.** [KtlintConventionPlugin.kt:15](https://github.com/komi-store/komi-store/blob/cfa6bd30e6b35cbbc369d78a4599182a9a66beac/build-logic/convention/src/main/kotlin/KtlintConventionPlugin.kt#L15) excludes `**/generated/**`, but ktlint-gradle matches patterns relative to each source root, so KSP Room code and Compose resource accessors were linted too: 104,706 extra violations from generated files. Excluding by absolute path (`it.file.invariantSeparatorsPath.contains("/build/")`) fixes it.
2. **The format-on-build hook breaks once ktlint is on everywhere.** [build.gradle.kts:21-34](https://github.com/komi-store/komi-store/blob/cfa6bd30e6b35cbbc369d78a4599182a9a66beac/build.gradle.kts#L21-L34) makes `preBuild` and compile depend on `ktlintFormat`. In `core:data` that creates a task cycle through KSP (`preBuild -> ktlintFormat -> kspDebugKotlinAndroid -> preDebugBuild`). It also rewrites sources during a compile.
3. **compose-rules 0.6.1 and later crash on ktlint 1.8.0.** They are built with Kotlin 2.4 and call a stdlib function the ktlint worker does not have (`NoSuchMethodError: sequenceOf`). 0.6.0 is the newest release built on Kotlin 2.2.21 and runs fine.

### D4. How to roll ktlint out

Measured in section 2:

- **Option A (recommended):**
  - One mechanical `ktlintFormat` PR at a quiet moment: 551 files, compile-checked in a trial run.
  - Add its commit to `.git-blame-ignore-revs`.
  - Fix or baseline the 201 that remain, then fail CI on new violations.
  - Cost: open PRs and volunteer branches need a rebase.
- Option B: a ktlint baseline of all 6,184 violations and no mass format. ktlint baselines match on line and column, so any edit that shifts lines re-surfaces old violations in touched files. That causes noise for months.
- Option C: format module by module over several PRs. Smaller rebases, but CI can only gate modules that are done.
- Since then [#1056](https://github.com/komi-store/komi-store/pull/1056) runs ktlint through Spotless on files changed against `main`, so formatting blocks from day one without baselines. The one-time format still matters: until it lands, touching a file means reformatting all of it in that PR.
