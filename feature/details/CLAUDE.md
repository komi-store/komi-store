# Details Feature

Repository detail screen: owner, stats, releases with download/install, readme (with translation), per-app install/update flow. Plus full-README, release-notes and markdown-viewer sub-screens. Most complex feature.

## Structure

```text
feature/details/
  domain/          # DetailsRepository, TranslationRepository, AttestationVerifier, InstallationManager
  data/            # impls; translation/ has one Translator per TranslationProvider; ReadmeLocalizationHelper, preprocessMarkdown
  presentation/
    Details*         # main screen; RawDetailsState -> DetailsState via RawDetailsStateMapper
    about/           # full README (AboutRoot, DetailsAboutViewModel)
    whatsnew/        # release notes (WhatsNewRoot, DetailsWhatsNewViewModel)
    markdownviewer/  # linked .md files (MarkdownViewerRoot, MarkdownViewerViewModel)
```

## Navigation

`GithubStoreGraph.DetailsScreen(repositoryId, owner, repo, isComingFromUpdate, sourceHost, packageName)`. Loads by owner+name when both are set (deep links), else by `repositoryId`. Sub-routes: `DetailsAboutScreen`, `DetailsWhatsNewScreen`, `MarkdownViewerScreen(url)`; Details also opens `RepoIssuesScreen` / `RepoSecurityScreen` (feature/repo-pages) from the Issues and Security stat tiles (`sections/Stats.kt`; GitHub repos only, so Forgejo repos have no Security tile).

## Notes

- README language detected via `ReadmeLocalizationHelper.detectReadmeLanguage`; markdown via `multiplatform-markdown-renderer` + `MarkdownImageTransformer` (core/presentation). Translation via `TranslationRepository` + `LanguagePicker`.
- `SmartInstallButton` adapts to install state. Installing an older version first shows the downgrade dialog (`DowngradeWarning`, declared in `model/ShowDowngradeWarning.kt`).
- Android installer paths: Default / Shizuku / Dhizuku / Root. Root via libsu `Shell` (`RootServiceManager`). Dhizuku installs without installer attribution below Android 14 (`setInstallerPackageName` is 14+); on 14+ a `PENDING_USER_ACTION` answer retries without it.
- **Multi-OS picker (E15):** `ReleaseAssetsItemsPicker` toggle flips `TweaksRepository.showAllPlatforms`. ON -> assets group by `assetPlatformOf` into `PlatformSectionCard`s with "Your device"/"For transfer" chips. Non-current asset -> `OnDownloadForTransfer` -> `BrowserHelper.openUrl`.
- **Coachmarks:** APK Inspect button and ReleaseChannel chip, each a pulse + `KomiCoachmark` (core/presentation), which points at its anchor and stays until "Got it". One-shot via `TweaksRepository.get*CoachmarkShown`.
- **Self-owned badge (E20):** `AppHeader` shows a `Verified` icon next to the owner login when `state.isCurrentUserOwner`. Reactive via `combine(userSessionRepository.getUser(), repository.owner.login)`.
- **Skip release (E542):** per-app `skippedReleaseTag` on `InstalledApp` keeps `isUpdateAvailable` false, so `SmartInstallButton` shows no update CTA; the update check clears it once a strictly newer release lands. Confirming a downgrade from the latest release sets it to that latest tag.
- **Forgejo / Codeberg branch:** `DetailsRepositoryImpl.getRepositoryByOwnerAndName / getAllReleases / getReadme / getRepoStats / getLatestPublishedRelease` accept `sourceHost: String? = null`. Non-null -> `ForgejoApiClient` direct call (no backend mediator). README from `/contents/README.md?ref={branch}` (Forgejo lacks `/readme`), else the first `README*` in the root listing; license sniffed from the header text of `LICENSE` / `LICENSE.md` / `LICENSE.txt` / `COPYING`; downloads aggregated by summing asset `download_count`. CRLF release bodies normalized so GFM tables render. Foreign-source `getUserProfile` skipped (GitHub-only). `AppHeader` avatar falls back to `repository.owner.avatarUrl` when profile null.
- **Multi-flavor primary picker (#638):** with no asset selected, `pickPrimaryInstalledApp` prefers the `isUpdateAvailable=false` variant, else `first()`. Prevents false "Update" CTA when a project ships multiple packages (e.g. generic + Play APK) and only one variant is current.
- **Multi-app repos (#970):** with an asset selected, `pickPrimaryInstalledApp` delegates to `AssetOwnership.ownerOf` (`core/domain`): asset filter -> glob (`AssetVariant.familyGlobs`) -> stem (`extractBaseStem` / `tagStem`), ties broken by major version (Godot `editor.v3` / `.v4` share every name token but the version), else null so a different app in the same repo can be installed. A sole app whose own asset family is missing from the release is kept only for a real rename (all new-name releases newer than all old-name ones); apps released side by side (K-9 / Thunderbird tags) interleave and stay separate. `recomputeAssetsForRelease` narrows to the anchor asset's family (filter, else stem) before the variant resolver, so pinned tokens can't land on another app's APK. `loadInitial` opens on the newest release in the installed channel whose chosen APK the opened app owns. Stem = which app (ignores ABI/flavor); glob = which variant (keeps them). Names are compared both by the version pattern and with their own release's version (and any adjacent build id or hash) removed via the release tag; either match counts. Rename detection stays name-only.
- **Installed-app switcher:** when the repo has 2+ installed apps (or one not bound to the selected asset), `AppHeader` shows a chip per installed app in a `LazyRow`; the selected chip is the app the CTA acts on and scrolls into view. Tapping sends `OnSelectInstalledApp` -> `switchToInstalledApp`, which opens that app's newest owned release (current channel, else any). The plain "Installed" pill is hidden while the switcher shows; update/pending pills stay. The downgrade dialog names the target app (icon, name, package) and "Uninstall first" removes `DowngradeWarning.packageName`.
- **Platform-aware releases:** "device build" = a release with an asset `installer.isAssetInstallable` accepts (`deviceBuildReleaseIds`); a release's platforms = `assetPlatformOf` over its assets (`releasePlatforms`). `loadInitial` / retry / channel switch open on the newest device build in the channel, else the newest release. `AppHeader` chips = `newestReleasePerPlatform` over the channel (device first, year suffix when older than 365 days). Device chip jumps to the device build; other chips open `PlatformHandoffSheet` (share link / open in browser per asset). Hints in `header`: "Newer releases have no build for this device" (opens picker) and "Go to <tag>" under the CTA when the selected release has no device build. `VersionPicker` rows show platform icons, "No build for this device", "Latest for <platform>". In a monorepo (`ReleaseLines.isMultiLine`: tag prefixes like `auth-v*` / `photos-v*` that interleave), the chips, the newer-releases hint and the device-build jump only look at the selected release's line (`RawDetailsState.releaseLines`, computed once per release load), so viewing ente Auth never shows Photos' or Ensu's versions. Same lines drive the monorepo UI: the Versions field shows the bare version plus the app name (`DetailsState.selectedAppLabel`, `utils/releaseLineLabel`: `auth` -> `Auth`, unnamed line -> repo name), the version sheet gets an All / per-app chip row preset to the viewed app ("Latest" is then per app), and when no installed app owns the selected release the header's switcher row leads with a selected chip naming the app; tapping it opens the version sheet.
- **Manual refresh feeds the Library:** after `DetailsAction.Refresh` reads the releases, `syncLibraryUpdateState` passes them to `InstalledAppsRepository.checkForUpdatesWithReleases` for every installed app of the repo, so the Library's update state matches the refreshed page. A list without the app's release changes nothing; the silent revalidation on open never writes update state.
- **Content width:** `contentWidthCap()` (core/presentation) caps the list at a fraction of the window per `LocalContentWidth` (`COMPACT` 0.55 default, `WIDE` 0.75, `EXTRA_WIDE` 0.95), clamped to 480..1600dp. Set in `Tweaks -> Look & feel` (desktop only). Outer Box's `Modifier.scrollable(state = listState, reverseDirection = true, enabled = isDesktop)` forwards mouse-wheel events from empty side gutters to the LazyColumn; off on Android to avoid a second scrollable contending with LazyColumn touch.
- **Markdown perf:** Chunked progressive rendering (`splitMarkdownIntoChunks`, ~4000 chars). Pre-processing (theme-aware images + `separateAdjacentImageLinks`) on `Dispatchers.Default`. `MarkdownComponents` memoized; `TranslationState @Immutable`. Together kills download-progress-driven recomp storms.
- **Markdown image link awareness:** `LinkAwareMarkdownImage` walks `ASTNode.parent` for `INLINE_LINK`, makes badge images clickable to outer href. `MarkdownImageTransformer` adds browser-like User-Agent + accept header to bypass CDN hotlink protection on common badge services.
