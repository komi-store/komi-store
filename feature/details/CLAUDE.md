# Details Feature

Repository detail screen: owner, stats, releases with download/install, readme (with translation), per-app install/update flow. Plus full-README, release-notes and markdown-viewer sub-screens. Most complex feature.

## Structure

```text
feature/details/
  domain/          # DetailsRepository, TranslationRepository, AttestationVerifier, InstallationManager
  data/            # impls; translation/ has one Translator per TranslationProvider; ReadmeLocalizationHelper, preprocessMarkdown
  presentation/
    Details*         # main screen; RawDetailsState -> DetailsState via RawDetailsStateMapper
    about/           # full README (AboutRoot, DetailsAboutViewModel)
    whatsnew/        # release notes (WhatsNewRoot, DetailsWhatsNewViewModel)
    markdownviewer/  # linked .md files (MarkdownViewerRoot, MarkdownViewerViewModel)
```

## Navigation

`GithubStoreGraph.DetailsScreen(repositoryId, owner, repo, isComingFromUpdate, sourceHost, packageName)`. Loads by owner+name when both are set (deep links), else by `repositoryId`. Sub-routes: `DetailsAboutScreen`, `DetailsWhatsNewScreen`, `MarkdownViewerScreen(url)`; Details also opens `RepoIssuesScreen` / `RepoSecurityScreen` (feature/repo-pages) from the Issues and Security stat tiles (`sections/Stats.kt`; GitHub repos only, so Forgejo repos have no Security tile), and `ReviewsScreen` (feature/reviews) from the Ratings & reviews section.

## Notes

- README language detected via `ReadmeLocalizationHelper.detectReadmeLanguage`; markdown via `multiplatform-markdown-renderer` + `MarkdownImageTransformer` (core/presentation). Translation via `TranslationRepository` + `LanguagePicker`.
- **Auto-translate:** the Tweaks setting fills `aboutTranslation` / `whatsNewTranslation` on open and on a release pick; `RawDetailsStateMapper` renders those texts in the About and What's New sections while the translation is shown and leaves the raw fields untouched. A blank target, a key-based provider without credentials or a failed request leaves the original text with no error surface. Turning the setting off clears the automatic translations.
- `SmartInstallButton` adapts to install state. Installing an older version first shows the downgrade dialog (`DowngradeWarning`, declared in `model/ShowDowngradeWarning.kt`).
- Android installer paths: Default / Shizuku / Dhizuku / Root. Root via libsu `Shell` (`RootServiceManager`). Dhizuku installs without installer attribution below Android 14 (`setInstallerPackageName` is 14+); on 14+ a `PENDING_USER_ACTION` answer retries without it.
- **Multi-OS picker (E15):** `ReleaseAssetsItemsPicker` toggle flips `TweaksRepository.showAllPlatforms`. ON -> assets group by `assetPlatformOf` into `PlatformSectionCard`s with "Your device"/"For transfer" chips. Non-current asset -> `OnDownloadForTransfer` -> `BrowserHelper.openUrl`.
- **Coachmarks:** APK Inspect button and ReleaseChannel chip, each a pulse + `KomiCoachmark` (core/presentation), which points at its anchor and stays until "Got it". One-shot via `TweaksRepository.get*CoachmarkShown`.
- **Icon colors:** in Classic, `DetailsRoot` wraps the screen and its sheets and dialogs in `KomiSeededTheme`, seeded by `rememberIconSeedColor` (the installed app's icon, else the owner's avatar), so the page takes the app's colors. Manga and the Mono accent keep their own.
- **Header look:** `AppHeader` is one `KomiSurface` with `KomiSurfacePaper.Tinted`. In Classic the picture sits on a cookie-shaped plate (`MorphShape`, a circle while a download runs) with the install status as a `StatusBadge` burst on its corner; the title uses `displayEmphasized`; and the platform tiles form one connected group (round ends, the device's tile a wider pill). The picture pops in and the tiles rise in one after another, once per visit (a saveable flag, so scrolling back doesn't replay it). Manga keeps an ink panel with the status as a tilted sticker. A tile shows its platform's icon over the newest build's version, or the year when that build is older than 365 days.
- **Self-owned badge (E20):** `AppHeader` shows a `Verified` icon next to the owner login when `state.isCurrentUserOwner`. Reactive via `combine(userSessionRepository.getUser(), repository.owner.login)`.
- **Skip release (E542):** per-app `skippedReleaseTag` on `InstalledApp` keeps `isUpdateAvailable` false, so `SmartInstallButton` shows no update CTA; the update check clears it once a strictly newer release lands. Confirming a downgrade from the latest release sets it to that latest tag.
- **Forgejo / Codeberg branch:** `DetailsRepositoryImpl.getRepositoryByOwnerAndName / getAllReleases / getReadme / getRepoStats / getLatestPublishedRelease` accept `sourceHost: String? = null`. Non-null -> `ForgejoApiClient` direct call (no backend mediator). README from `/contents/README.md?ref={branch}` (Forgejo lacks `/readme`), else the first `README*` in the root listing; license sniffed from the header text of `LICENSE` / `LICENSE.md` / `LICENSE.txt` / `COPYING`; downloads aggregated by summing asset `download_count`. CRLF release bodies normalized so GFM tables render. Foreign-source `getUserProfile` skipped (GitHub-only). `AppHeader` avatar falls back to `repository.owner.avatarUrl` when profile null.
- **Release read order:** for a GitHub repo, `DetailsRepositoryImpl.getAllReleases` reads the cache, then the backend, then api.github.com only when the backend fails over (`shouldFallbackToGithubOrRethrow`) or answers with an empty list, since its copy can lag behind the host. A refresh (`preferDirectSource`) reads the host first, without the stale copy, then the backend. After an empty backend answer only a rate limit fails the read; any other host failure keeps the empty answer. A failed read throws (after the stale copy when `allowStale`) instead of returning an empty list, so Details shows the failed card only for a thrown read and the empty card for a repo with no releases.
- **Multi-flavor primary picker (#638):** with no asset selected, `pickPrimaryInstalledApp` prefers the `isUpdateAvailable=false` variant, else `first()`. Prevents false "Update" CTA when a project ships multiple packages (e.g. generic + Play APK) and only one variant is current.
- **Multi-app repos (#970):** with an asset selected, `pickPrimaryInstalledApp` delegates to `AssetOwnership.ownerOf` (`core/domain`): asset filter -> glob (`AssetVariant.familyGlobs`) -> stem (`extractBaseStem` / `tagStem`), ties broken by major version (Godot `editor.v3` / `.v4` share every name token but the version), else null so a different app in the same repo can be installed. A sole app whose own asset family is missing from the release is kept only for a real rename (all new-name releases newer than all old-name ones); apps released side by side (K-9 / Thunderbird tags) interleave and stay separate. `recomputeAssetsForRelease` narrows to the anchor asset's family (filter, else stem) before the variant resolver, so pinned tokens can't land on another app's APK. `loadInitial` opens on the opened app's update target when it has one (`updateTargetOf`: `latestReleaseId`, else the tag), else on the newest release in the installed channel whose chosen APK the app owns. Stem = which app (ignores ABI/flavor); glob = which variant (keeps them). Names are compared both by the version pattern and with their own release's version (and any adjacent build id or hash) removed via the release tag; either match counts. Rename detection stays name-only.
- **Installed-app switcher:** when the repo has 2+ installed apps (or one not bound to the selected asset), `AppHeader` shows a chip per installed app in a `LazyRow`; the selected chip is the app the CTA acts on and scrolls into view. Tapping sends `OnSelectInstalledApp` -> `switchToInstalledApp`, which opens that app's newest owned release (current channel, else any). The plain "Installed" status is hidden while the switcher shows; update/pending stay. The downgrade dialog names the target app (icon, name, package) and "Uninstall first" removes `DowngradeWarning.packageName`.
- **Platform-aware releases:** "device build" = a release with an asset `installer.isAssetInstallable` accepts (`deviceBuildReleaseIds`); a release's platforms = `assetPlatformOf` over its assets (`releasePlatforms`). `loadInitial` / retry / channel switch open on the newest device build in the channel, else the newest release. `AppHeader` platform tiles = `newestReleasePerPlatform` over the channel (device first, the year instead of the version when older than 365 days). The device tile jumps to the device build; other tiles open `PlatformHandoffSheet` (share link / open in browser per asset). Hints in `header`: "Newer releases have no build for this device" (opens picker) and "Go to <tag>" under the CTA when the selected release has no device build. `VersionPicker` rows show platform icons, "No build for this device", "Latest for <platform>". In a monorepo (`ReleaseLines.isMultiLine`: tag prefixes like `auth-v*` / `photos-v*` that interleave), the platform tiles, the newer-releases hint and the device-build jump only look at the selected release's line (`RawDetailsState.releaseLines`, computed once per release load), so viewing ente Auth never shows Photos' or Ensu's versions. Same lines drive the monorepo UI: the Versions field shows the bare version plus the app name (`DetailsState.selectedAppLabel`, `utils/releaseLineLabel`: `auth` -> `Auth`, unnamed line -> repo name), the version sheet gets an All / per-app chip row preset to the viewed app ("Latest" is then per app), and when no installed app owns the selected release the header's switcher row leads with a selected chip naming the app; tapping it opens the version sheet.
- **Manual refresh feeds the Library:** after `DetailsAction.Refresh` reads the releases, `syncLibraryUpdateState` passes them to `InstalledAppsRepository.checkForUpdatesWithReleases` for every installed app of the repo, so the Library's update state matches the refreshed page. A list without the app's release changes nothing; the silent revalidation on open never writes update state. The rewritten row reaches the page through `observeInstalledApp`; when the opened app's update state changed, the page also moves to the new update target, unless the user picked a release, asset, channel or app since it opened (`hasUserPickedRelease`).
- **Content width:** `contentWidthCap()` (core/presentation) caps the list at a fraction of the window per `LocalContentWidth` (`COMPACT` 0.55 default, `WIDE` 0.75, `EXTRA_WIDE` 0.95), clamped to 480..1600dp. Set in `Tweaks -> Look & feel` (desktop only). Outer Box's `Modifier.scrollable(state = listState, reverseDirection = true, enabled = isDesktop)` forwards mouse-wheel events from empty side gutters to the LazyColumn; off on Android to avoid a second scrollable contending with LazyColumn touch.
- **Markdown perf:** Chunked progressive rendering (`splitMarkdownIntoChunks`, ~4000 chars). Pre-processing (theme-aware images + `separateAdjacentImageLinks`) on `Dispatchers.Default`. `MarkdownComponents` memoized; `TranslationState @Immutable`. Together kills download-progress-driven recomp storms.
- **Markdown image link awareness:** `LinkAwareMarkdownImage` walks `ASTNode.parent` for `INLINE_LINK`, makes badge images clickable to outer href. `MarkdownImageTransformer` adds browser-like User-Agent + accept header to bypass CDN hotlink protection on common badge services.
- **Ratings & reviews (`sections/Reviews.kt`):** between What's New and About. `loadReviewsPreview` reads the first page from `ReviewsRepository` after the repo loads and on refresh, and again when `ReviewsRepository.changes` names this repo. The section shows the summary, Rate this app (five stars, hidden for the owner: a tap fills the row, then opens the Reviews screen with the composer at that rating, the installed version else the selected release, and `selectedAppLabel`), the top 3 reviews (read-only) and See all. A failed read leaves `reviewSummary` null, which hides the section.
- **HTML tables in READMEs:** the renderer has no HTML tables, so `preprocessMarkdown` turns each `<table>` cell into its own block and drops the cells' indentation (after a blank line, 4+ spaces would render as code). Team and contributor grids stack vertically.
